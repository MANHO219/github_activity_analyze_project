# 六小时运行与复核

## 环境和启动

使用报告中 Ubuntu/Python/Java/Spark 版本，三台共享 /data/cs5488；代码位于 /data/cs5488/project。configs/ 是实测配置。先检查挂载与环境，在 Master、两个 Worker 分别执行：

```bash
bash /home/lishuo/cs5488-cluster/bin/cluster_service.sh check
```

仅 D4 需要依次在 Master、两个 Worker 执行同脚本的 start。L1/L4 在 Worker 1 提交，实际 VM vCPU 分别为 1/4；CPU 配置调整只能在 VM 正常关机后进行。D4 在 Master 提交，两 Worker 各提供 2 核。

```bash
source /home/lishuo/cs5488-cluster/conf/spark-env.sh
S=/data/cs5488/project/d_parallel_experiments/scripts
# 以下为历史提交示例，旧 ID 已存在，复现必须换用新的唯一 ID。
bash "$S/submit_run.sh" L1 6 l1_6h_r1
bash "$S/submit_run.sh" L4 6 l4_6h_r1
bash "$S/submit_run.sh" D4 6 d4stable_6h_r1
```

三条命令属于不同节点/资源状态，不能在同一节点按顺序直接执行。submit_run.sh 保存实际计时与环境，展开 spark-submit 参数；run_experiment.py 使用与 A 相同的清洗逻辑，只启用 benchmark 参数。

## 测量选择与证据路径

正式 ID：l1_6h_r1、l1_6h_r2、l1_6h_r3_resume；l4_6h_r1/r2/r3；d4stable_6h_r1/r2/r3。

预热 ID：l1_6h_warmup、l1_6h_resume_warmup、l4_6h_warmup、d4stable_6h_warmup。预热不计入中位数。旧 d4_6h_r2 网络故障、旧 l1_6h_r3 用户暂停，均不计入有效测量；旧网卡配置下的全部 D4 数据不与修复后混算。

results/completed_20261111/measurements/<run_id>.json 是原始计时；同名 _environment.json 为环境/代码哈希，_evidence.json 为任务参与、输出指纹、质量检查。runs/<run_id>/ 为应用 ID、有效 Spark 配置与输入/质量元数据。正式三次中位数用于加速比与吞吐，详见 six_hour_comparison.json。

## 复核

每次成功输出后，在环境中执行 `python "$S/summarize_run.py" <run_id>`，它读取共享完整输出和原始事件日志。九次完成后 `python "$S/compare_experiments.py"` 会核对输出、输入、处理代码及资源设置，生成 six_hour_comparison.json。该脚本选择的是本次固定 ID，不是任意 24h Python 对账入口。

CSV 核对解压后的完整有序内容 SHA-256；Parquet 核对 schema、行数及完整行 SHA-256 模和（含重复次数），属于哈希核对而非逐行差异报告。稳定性复核统计原始 SparkListenerTaskEnd、StageCompleted、ExecutorRemoved 与 ApplicationEnd，完整日志见证据包说明。

仅有 Git 精简证据可以复查记录和统计，不能冒充独立重跑完整数据。六小时 Python 对账已补交；下一阶段由 D 基于 A 已共享的一周滚动程序适配日期、批次及月级 Spark 处理，正式扩大输入与验证范围按后续计划确定。

## 六小时对账复跑入口

后续复跑使用 `scripts/run_reconciliation.py` 和 `scripts/collect_reconciliation.py`。`results/python_spark_6h_20261111/execution/` 是历史实际执行快照，原脚本、哈希与归档校验值继续保留。

新入口校验同一批 2024-01-15 UTC 0–5 时原始档案，并用原有 Python 清洗与两套比较器核对已有 Spark 输出，不启动 Spark。以下命令在实际挂载原始数据和 Spark 输出的环境中执行；输出目录和归档文件必须使用新的名称，路径按自己的环境调整。

```bash
cd /data/cs5488/project
PY=/home/lishuo/cs5488-round1/env/bin/python
"$PY" d_parallel_experiments/scripts/run_reconciliation.py \
  --raw-dir /data/cs5488/raw \
  --spark-run /data/cs5488/runs/d4stable_6h_r1 \
  --output /data/cs5488/runs/python_6h_replay_02

"$PY" d_parallel_experiments/scripts/collect_reconciliation.py \
  --run-dir /data/cs5488/runs/python_6h_replay_02 \
  --archive /data/cs5488/python_6h_replay_02.tar.gz
```

`configs/reconciliation_code_lf.json` 对应本轮 `607f9c3` 处理代码的 LF 归一化哈希。只将源文件的 CRLF 统一为 LF 后比较；真正的代码改动仍会报错。新运行的 `code_sha256.json` 同时保留原始字节哈希和归一化哈希，并将本次预期清单复制到输出目录。原始档案、结果文件和历史日志的哈希仍按原始字节计算。后续处理逻辑变更时，需明确记录新基线，不能用旧清单假称复现原实验。

任一比较返回 false 或发生异常，执行入口记录 `state=error` 并以退出码 1 结束。打包入口要求状态、两项通过标记及两份比较报告均通过，再复核 Spark 四份导出的指纹；不满足时非零退出，不创建归档。新归档包含本次实际使用的修订脚本，不覆盖历史归档。

无需 JVM 的小样本验证可从仓库根目录执行：

```bash
python -m unittest discover -s d_parallel_experiments/tests -v
```

这些入口仅用于六小时对账交接；日期与批次通用化、月级 Spark 滚动处理仍由 D 按后续计划适配。
