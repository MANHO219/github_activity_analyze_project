# 六小时测量中的网络故障与恢复

2026-11-10，旧 D4 组预热及 r1 完成，r2 期间 Worker 2（192.168.20.131）失联。Master 报告 Worker 心跳超时，Windows SSH 超时，Master 的邻居记录为 INCOMPLETE；不能归因于本机工具权限。

受影响作业 `app-20261110113132-0003` / `d4_6h_r2` 已定向终止，原始记录保留：282.606 秒，退出码 143。此次数值不进入有效性能统计。

通过 VMware Tools 正常重启后恢复 SSH，上一启动的内核日志反复显示 `e1000 ... ens33: Detected Tx Unit Hang`，并伴有 NFS server not responding。原始日志保存在共享目录 `/data/cs5488/measurements/worker2_previous_kernel.log`；Windows VMware 日志备份在本地完整材料中，Git 仅保留本摘要。

恢复措施：

1. 确认没有测量运行后正常关闭 Worker 2。
2. 备份 Worker 2 的 VMX 配置文件 为 `.before-vmxnet3-20261110`。
3. 仅将 `ethernet0.virtualDev` 从 `e1000` 改为来宾已安装驱动的 `vmxnet3`，保持 MAC、CPU、内存和磁盘不变。
4. 启动后接口变为 `ens192`，IP 仍为 192.168.20.131，严格 SSH 身份验证通过，驱动确认是 vmxnet3。
5. 开机 NFS 挂载因网络尚未就绪失败；用户在控制台执行 `sudo mount /data/cs5488`，随后 `cluster_service.sh check` 通过。

更换网卡是根据本次实测故障采取的恢复尝试，不声称已证明所有 e1000 或 vmxnet3 环境的稳定性。VMware Workstation 的虚拟网卡类型配置方式可参阅 [Broadcom Workstation 说明讨论](https://community.broadcom.com/vmware-cloud-foundation/communities/community-home/digestviewer/viewthread?CommunityKey=fb707ac3-9412-4fad-b7af-018f5da56d9f&GroupId=7171&MessageKey=e3d338d1-fb49-47bb-9bd2-2e3fee16eb5f)。

正式 D4 已使用 `d4stable_6h_*` 新目录重新预热和完成三次测量。旧 D4 的预热、r1 和失败 r2 均保留，但不与新网卡配置下的结果混算。L1/L4 计算节点及共享存储服务器配置不因本次 Worker 2 网卡更改而改变。
